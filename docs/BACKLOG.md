# BACKLOG(已知但刻意未做)

| 項目 | 觸發條件 |
|---|---|
| Canvas/SVG 圖表取值(需讀圖表庫內部資料或 OCR) | 使用者提出實際目標頁是 canvas 圖表時 |
| 逐站 `optional_host_permissions` 取代 `<all_urls>` | 要上架 Chrome Web Store 時(審核會要求) |
| 自動落地 JSON(File System Access 選資料夾,需偶爾重授權) | 使用者需要不用手動就有檔案時 |
| Native Messaging host 寫任意路徑、完全無人值守 | 上一項仍不夠時(多一個安裝步驟) |
| 深色模式以外的主題色 | 使用者提出 |
| 秒級抓取 | 目前最小 1 分鐘;alarms 下限 30 秒,再快要常駐分頁 |
| Firefox 支援 | 有需求時;選擇器與 alarms API 皆可移植,contextMenus 差異最大 |
| Chrome Web Store 與 Edge Add-ons 上架 | 使用者想分享給別人安裝時(兩邊分別審核) |
| 任務設定 `storage.sync` 自動同步 | 使用者常在多台機器切換且嫌手動匯入麻煩時 |
| 抓取時同時截圖存證 | 使用者需要查證抓到的值時 |
| 同一頁多元素合併為一個任務(一次抓多值) | 使用者一頁要抓 5 個以上的值時 |
| Picker 設定 `attr` / `child` / `label` 策略的參數 | 目前這三個主策略在 Picker 選得到但沒有欄位填參數,等於選了必定失敗的策略;有站台需要時補欄位(或先從下拉移除) |
| Picker 設定乘數與小數位數 | `extract.js` 支援 `multiplier`/`decimals`,但只能靠匯入設定檔設定 |
| 任務層級的 `precheckLeadMinutes` 介面 | 程式支援,Picker 沒有欄位 |
| `lateTolerance`(遲到容忍度) | 規格寫了但沒實作;`late` 目前只來自補抓 |
| 同時最多 2 個站台並行的全域佇列 | 目前只有同站台串行;使用者任務多到互相拖慢時 |
| HTTP 錯誤頁(標題含 `ERR_`)視同 not_found | 使用者反映抓到錯誤頁卻被當成成功時 |
| 錯過清單項目超過 7 天自動略過 | 目前只限制新算入的範圍,既有項目不會過期 |
| 燈號的圖示變體(`setIcon`) | 圖示檔已產好(`icons/icon-{green,yellow,red,gray}-*.png`),但 `applyBadge` 目前只設 badge 不換圖 |
| 預檢 / 站台檢查 / 找不到元素的通知點擊路由 | 目前只有告警通知點得動 |
| popup 顯示「下次預檢」與「暫停」按鈕 | 規格 §12.2 提到,目前只有立即重試與開啟頁面 |
| 看門狗清掉卡住的執行後重新排入 | 規格 §4.1 寫「標 interrupted 並重新排入」,目前只清掉並記診斷;那個槽要等下一次排程 |
| Shadow DOM 內的元素 | 選取模式選不到目標(常見於 Web Components 站台) |
| 跨頁分頁的表格 | 要聚合的資料在第 2 頁以後時 |
| OAuth / 跨 origin 的登入流程 | 登入頁在別的網域時(目前只支援同 origin 的表單登入) |
| 同一站台多組帳號 | 使用者同一個網站有兩個帳號要分別抓時 |
| 「測試登入」按鈕(站台設定視窗內即時驗證) | 使用者反映設定完不知道對不對時 |
| 含密碼的設定匯出(換機沿用) | 使用者要換電腦時;本機金鑰的密文換機解不開,需改以密語重新加密 |
| `web_accessible_resources` 收斂成單一 bundle | 上架審核要求、或有人反映網頁可探測到本擴充功能時(需要打包步驟,與「無框架原生 JS」慣例衝突) |
| 前置動作支援輸入文字、捲動到底 | 目前只有等元素/點元素/等待;有站台需要時 |
| 告警觸發時 POST 到 webhook | 使用者要接自動化時(`shared/alerts.js` 的 hits 就是觸發點) |
| iframe 內元素 | 目標值在跨域 iframe 內時(需 allFrames 注入) |
| 英文介面 / i18n | 上架 Chrome Web Store 或要分享給非中文使用者時 |
| 從 Distill / Visualping 匯入任務 | 有使用者提出時 |
| 互動版獨立 HTML 報表(目前是靜態快照) | 使用者需要在匯出檔內切換範圍或篩選時 |
| 值未變化時不寫紀錄的選項 | 紀錄量成為問題、保留天數設定已不夠用時 |
| 既有三處拖曳(卡片移動縮放、儀表板頁籤、任務清單)改用 `ui/report/dnd.js` | 那三處要改動時順手搬;AF-4 只讓新拖曳走它,重構既有的風險大於收益 |
| 樞紐表桶內多筆的其他合併策略(平均、最大、加總) | 目前固定取最新的成功值;使用者提出要別的統計時 |
| interval 任務的錯過補抓 | 目前 interval 不進錯過清單(一個週末上百槽);使用者明確要求補抓時 |
| `pruneCardsForTask` 刪掉整張卡片不可復原 | 任務刪除時來源歸零的卡片會被整張移除,undo 只在編輯模式的記憶體內;使用者反映誤刪時 |
| 歷史頁的「依一天中的時刻分組」略過沒有 slot 的紀錄(`logic.js`) | 使用者反映補抓/手動紀錄在該視圖缺席時 |
| 非編輯模式仍渲染隱藏的移除把手(匯出 HTML 夾帶死元素) | 匯出檔大小成為問題時;需改成切換編輯模式時重繪卡片 |
| 任務刪除/停用後已排定的重試 alarm 不會被看門狗清掉(觸發時會被擋,純殘留) | 有人反映 alarm 清單有垃圾時 |
| 拖曳投放的行動裝置/觸控適配 | 目前只在桌面滑鼠驗證過;有平板需求時 |
| 拖曳的鍵盤替代操作(無障礙) | 有鍵盤或輔助技術使用者提出,或上架審核要求時 |
| 儀表板卡片虛擬化 | 單一儀表板卡片超過 30 張且重畫變慢時 |
| 儀表板匯出成圖片(PNG) | 使用者要把儀表板貼進簡報時 |
