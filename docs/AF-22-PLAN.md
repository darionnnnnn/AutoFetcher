## 1. 已確認的方向與規劃取捨

使用者已選擇：

1. 群組管理放在 Chrome 右側 AutoFetcher 設定面板。
2. 同一個頁面上的值都能選入同組，不以表格或獨立元素限制群組。
3. 本輪修正完成鈕沒有可讀文字、游標接近時左右跳動而無法點擊。
4. 本回合撰寫規劃，不實作。

以下為原規劃契約，第二次複檢補強見 §13；涉及頁面狀態、關閉草稿與雙擊完成的條目先依 §13.3 討論，不能把建議冒充使用者定案：

- 一個群組存成一個一般可排程任務，多個值沿用子序列；不產生隱藏子任務，也不另建永久群組資料表。
- 「同頁」指同一個目標分頁與它可存取的內嵌框架；包含主文件與 iframe 混選、巢狀 iframe。不同分頁、導覽至另一頁不算同一輪可直接混選的頁面。
- Chrome 限制注入的頁面／框架、closed shadow root 等實際不可存取內容，要明確提示原因，不能假裝已選或擷取成功；不是以表格結構設人為限制。
- 同一張表可分屬多個群組；同一值可以被不同群組選取。同組重複點同一值為取消選取，不建立重複項。
- 從頁面取名稱是一次性擷取文字，回填後可編輯；日後排程不跟著頁面文字改任務名。名稱不作為資料 key 或定位依據。
- 即使最後只有一組、一個值，也保留此建立流程及穩定值身分，不依數量突然切換表單或改變序列型態。
- 既有單任務建立入口繼續可用。新群組與舊任務的擷取、儲存、試抓共用核心，不維護兩套抓取引擎。

## 3. 使用者流程與操作契約

### 3.1 右側面板為唯一群組操作入口

1. 右鍵「一次建立多個任務」開啟面板，顯示「新增第一個群組」；此時頁面不能偷加值。
2. 新增群組後呈現名稱輸入與「從頁面取名稱」。輸入非空名稱後按「開始選值」。
3. 點「從頁面取名稱」時進入明確的取名狀態；點文字／欄位只回填名稱，不選值、不點開連結、不送出任務。空文字提示重選，不用空字串覆蓋既有名稱。
4. 取名後回到名稱欄確認，再開始選值。可改名，中文輸入法組字與 Enter 不得誤觸完成。取消取名只取消這一步，保留群組。
5. 選值時目前群組明顯標示；主頁、不同表格、獨立元素及可存取框架都加入此群組。點另一張表不換組。
6. 面板可切換群組、改名、移除值、移除群組、復原；按「新增群組」保留目前內容並開始下一組命名。
7. 固定底部主要動作「完成選取」檢查所有群組，轉到共用排程／去處／前置動作／試抓與儲存階段。空白名稱、零值組、失效來源逐組說明並可定位修正，不靜默丟掉。
8. 設定階段可「返回選取」繼續修改，保留設定與各組名稱。尚未儲存的群組不能因返回重選而變成另一份待存清單。

群組名可重複，不自動加尾碼改使用者指定名稱；畫面以群組順序和來源區分。群組、值各有穩定 key，排序、改名、移除別組不改 key。

### 3.2 頁面上的提示與鍵鼠

- 多任務模式以右側面板為主要完成入口；頁面保留高亮、目前選值模式與必要提示，不再維護另一份可獨立編輯的群組清單。
- 既有單任務／重選仍需頁面完成出口：完成、取消等操作位置固定，不因游標接近或按下而自動換邊。遮到內容時提供明確的手動移位／收合入口；不得把按鈕藏到使用者無法找回。
- 完成鈕始終有可讀文字與足夠點擊範圍。樣式隔離的具體方法於 A1 根因核對後選最小可驗證方案，不預先為整個 overlay 重寫架構。
- 原稿讓多任務雙擊／Enter 完成整批；複檢發現誤送與 click→click→dblclick 的選取語意風險，改列 §13.3 D03 待定案。無論採哪種快捷鍵，完成仍走同一份完整性檢查；焦點在 input／textarea／contenteditable、IME 組字、模態視窗或暫停選取時不得攔截成全域完成。
- 點一下加選／再點取消；拖曳、Shift 範圍、Ctrl+A、整欄合計、整欄每格、整列等都作用於目前群組。跨來源的範圍操作只在當次錨定的表內延伸，不把兩張表當同一張網格。
- 巢狀表的升級只改目前群組內對應來源，不得合併使用者建立的不同群組；既有值 key 與名稱不因可等價的座標換算重生。
- 其他群組已選值可以顯示次要標記；目前組另有文字／外框區分，不只靠顏色。同值在別組已選不妨礙目前組加選。
- 同一組刪到零值仍保留名稱；刪整組才移除。移除操作支援既有單步復原，快照包括群組、來源、值、名稱與當時作用組；不擴張為完整多步編輯歷史。
- 上限暫沿用 20 組、每組 100 個值；空草稿組計入組數。單格／獨立元素／整欄合計各算一值；整欄每格算展開後的值數。批次操作超限先提示將加入數量，不靜默截斷；零組與零值都不能完成。效能證據若要求調整數值，須回寫理由，不得藉限縮來源種類規避需求。

## 4. 資料模型與相容策略

### 4.1 任務與值的責任

- 任務層：id、name、頂層頁面 url、schedule、preActions、enabled、foreground 等原責任不變。
- task.fields 繼續保存穩定 key 與顯示名稱，供 series-index、告警、卡片與歷史使用。
- 新群組的每個值必須攜帶自己的來源（locator 與必要 frame 身分）及擷取規格。獨立元素可抓數字或文字，表格值保留 cell／block、inner、pos、skip、exclude、合計方式與策略參數。
- 建議公開表示採 task.mode／spec.mode = multi，spec.fields 的各項含 key、source 與 spec；source 表示定位／框架，spec 是可交給既有單目標擷取的規格。**此新增模式名稱與欄位名稱屬規劃暫定**，B1 可因實際序列化需求調整，但必須同步更新契約及全部消費端，不能留下兩種競爭表示。
- 不把同頁所有內容假裝成一張表，不用 body 當偽 locator，不把每個值變成可獨立排程的隱藏任務。來源表可共用解析結果，但效能快取不是永久身分。
- 新群組即使僅一值仍為具 field key 的任務，未來加值不導致序列從父 id 變成子 id。

### 4.2 舊資料

- 不批次重寫既有任務、紀錄與卡片來源。舊單值、舊同表多值仍可抓取、試抓、編輯、匯出入。
- 以共用正規化入口把舊任務的 task.locator／frame 與相對 field 規格組成可執行來源；不是讓每個呼叫端各自猜格式。
- 舊多值任務需要轉成跨來源時，原 task id、field key、使用者值名稱與歷史連續性保留。僅改名、排程、定位設定不轉格式、不重生 key。
- 舊單值任務新增第二個值涉及父序列變成子序列，是原本就存在的身分轉換；本輪不得宣稱能無成本接續。沿用原既有轉換與清理規則、保留歷史並在操作前說明，不擴張成全庫歷史搬遷。
- 新格式需明確版本界線。建議將 storage SCHEMA_VERSION 由 3 升 4，既有 1→2→3 遷移保留、4 不改紀錄鍵；匯出檔 data.schemaVersion 應讓舊版既有守門拒收新格式，不能讓舊版照 block 讀成錯值。具體版本調整由 B1 驗證現有初始化與遷移後定案；設定包 version 不無理由另改。
- validateTask 與匯入預覽共用驗證：來源與 spec 合法、key 唯一、task.fields 與 spec.fields 一致、frame 描述可用；未知模式或缺來源的 multi 任務拒收並說明。對合法舊格式不套新必填條件。
- 來源只描述任務目標頁面內的文件與元素，不能藉來源欄位另開其他頂層網址。既有外來設定拒絕 file: 的規則也要核對新來源描述，不能把本機檔案網址移到巢狀欄位就繞過。

### 4.3 值身分

- 比對至少包含來源框架／目標與相對擷取規格；兩張表相同列欄不得相配，兩個 frame 相同 locator 不得相配。
- 使用者名稱、預覽值、排序不是身分；skip／exclude 等既有非身分設定維持原規則。
- 同一個舊 key 只能被認領一次。重選回填帶原 key 與來源，並驗證所屬任務，不能直接相信任意訊息指定 key。
- 共用 field-match 完成新舊正規化、比對與 reconcile；main.applyRepick 與 picker.applyRetarget 都消費它。
- 移除值保留歷史，清除對應卡片來源與 lastValues；未移除值不能被誤清。

## 5. 草稿、訊息與框架生命週期

- background 透過 shared/storage 的 session 保存可序列化選取草稿，作為跨面板／frame 的單一事實來源；content 保留當前文件 DOM 快取，不能把 DOM 節點寫入 session。
- 草稿至少包含工作階段身分、版本、所屬 tab、群組與值 key、名稱、目前組、取名／選值／設定階段、共用表單及前置動作草稿。過期階段／已結束工作階段的回報一律不套用。
- 每次使用者選取變更以明確操作更新草稿；不因 mousemove 寫 session。讀改寫走既有鎖與 storage 入口；快速連點、切組、切框架不丟操作。UI 寫入失敗保留本地待處理內容並提示，不顯示已完成。
- 所有群組切換均帶穩定 group key；不能用陣列序號當身分。來源回報由 sender.tab／frame 身分核對，content 自報的 tab／frame 不作信任依據。
- 名稱選取、值選取、同步及完成若增加訊息型別，集中在 messages，分清 content 與擴充功能頁可送的命令；不得全面放寬 CONTENT_ALLOWED。
- 一個分頁可有多個 frame 的選取端；由工作階段協調啟用／暫停與清理。允許在面板選回主文件／已知框架，不再是只能往下鑽的死路；新插入／重載 frame 可重新附加且不能遺失其他來源。
- 永久規格不存 frameId。沿用 frames 唯一入口，以可再定位的框架描述判定；同 URL 多 frame 要用可核對身分消歧，無法唯一定位則失敗並說明，絕不隨便取第一個。
- SPA 替換選中元素、主頁導覽、frame 重載後，保留可見草稿並重新驗證來源。完成前不送已失效 DOM 快取；不能重定位的值標需重選，不能靜默刪掉整組。
- 切分頁／面板文件重載後依所屬 tab 恢復；保留原 RESOLVE_PANEL_TAB 與 sidePanel.open 手勢規則，不能靠當前作用分頁猜草稿歸屬。
- 面板重畫保留正在輸入的名稱、焦點、選字範圍與 IME；內容簽章含新草稿實際內容，避免更新不畫或每次更新整份重建。
- 取消取名返回群組；取消整輪沿用資料丟失確認精神（只有名稱、尚未選值也算未存內容）。明確放棄／完成儲存後清草稿與所有相關 frame 的 active／held 標記。**移除原稿「關閉面板沿用既有關閉語意」**：既有 closePanelFor 會刪 ctx，與恢復需求衝突；新群組關閉行為列 §13.3 D02。任何關閉策略都要停止所有 frame 的選取攔截。
- service worker 重啟能從 session 恢復；瀏覽器整體重啟不承諾保留 session 草稿。使用者可見行為需在教學說明，不改成永久自動保存任務。

## 6. 擷取、儲存與全專案影響

### 6.1 執行核心

- runTask 仍是任務執行入口，同站台佇列、fetch-tab、登入、前置動作、排程帳本、總時限與重試規則沿用。
- 在同一次任務執行內，依來源定位 frame／目標，按必要來源批次送擷取；相同表能共用一次解析，避免每值重新開頁或登入。
- 共用前置動作對任務執行一次，不因 N 個來源重放 N 次；內嵌框架需互動時沿用帶 frame 的前置動作規格。**這只足以處理準備後可共存的來源**；互斥頁籤／篩選／虛擬列等狀態切換列 §13.3 D01，未定案不得宣稱可排程抓取所有同頁狀態。
- 每個來源的定位→注入→捲動→擷取是可重試單位；沿用失去文件時有界重試、逾時不無限重送、前置動作不重放。各來源共享整次任務 deadline，不能變成「每值各拿完整總時限」。
- 健康來源不應因另一來源緩慢而永遠沒被處理；有界處理與整體超時後，尚未完成的值逐值回報逾時／中斷原因，不消失。
- 多來源擷取回覆仍按 field key，完整覆蓋宣告的值。缺回覆是該值失敗，不是成功也不是省略。零宣告值為設定錯誤，零成功值不得標成抓取成功。
- 失敗隔離：一來源找不到、frame 無權限或值解析失敗，不覆蓋已成功來源；全部失敗仍產生各值失敗資訊。混合結果沿用現有 health／ledger 成功判準，不偷偷改其語意。
- appendRecords 批次寫紀錄，父 task id 的帳本、health 與排程一次處理；子序列用 series-index。預覽逐格 items／blank 不進正式紀錄。
- dryRun 與排程走同一來源協調核心；dryRun 不寫正式紀錄、帳本與 lastValues。診斷按來源提供必要資訊，不只顯示第一張表的 HTML；保持上限，不擴張收集無關頁面內容。

### 6.2 UI 與其他消費端

- 群組列表須可看來源摘要、值數、每值預覽及試抓錯誤；數字與文字可混合，欄位可選既有數字／文字策略，不強制把整組當表格解析。
- 表格專有設定只影響適用值。共用合計方式、略過或位置設定有「套用哪些值」的明確規則，不能逐組 render 時洗掉不同來源既有設定。
- 沿用儲存核心：存任務成功後重建排程、觸發首次抓取、加卡片與回饋；部分儲存成功後重試不重建已存群組。保存階段與已存 task id 需回寫草稿，避免畫面重載重複新增。
- 儲存、試抓、返回選取不能互相重入。批次試抓期間保持原防重畫設計，完成後再套最新草稿。
- 每個待存群組在首次寫任務前固定對應 task id；存檔成功但草稿回寫前中斷，恢復時對帳並重用同一 id，不能另產新 id。排程重建／首次抓取／卡片等後續步驟要區分任務已存與步驟未完成，沿用既有去重入口。
- 任務編輯、重選、換目標、拆成每值一任務都支援新來源，不遺失 frame／spec。拆分沿用原設定並為每值取正確來源；不強行以群組第一個 locator 代入。
- describe／TERMS、任務頁、popup、摘要卡、儀表板與匯出顯示正確的多來源說明，不把新模式代碼直接顯示給使用者。
- series-index 若目前把父 task.mode 放進所有子序列，需讓新模式的數字／文字子值呈現正確；數字圖表、門檻告警不得對文字值套數字語意。既有 text 單任務規則維持。
- 已核對的型別消費端包括 shared/alerts.js:68 的相等比較、report/drop-rules.js:228 的投放判斷、drawer.js 的父／子選項與 templates.js:29 的數字序列篩選。混合群組投到數字卡片時依既有投放規則只納入可用數字來源，清楚提示不適用的文字來源；全為文字則拒絕。不能只修 series-index 而讓父任務入口繞過判斷。
- 設定匯出入、資料驗證、診斷、立即試抓的有目標守門、預檢／手動／排程各入口都要消費同一模型。凡重組 task／spec 的白名單都需逐處核對。
- 若新增 content 端共用模組，同步 manifest web_accessible_resources 的 import 閉包；背景仍用靜態 import。

### 13.2 狀態與執行順序補强

- UI 階段要明確列為：尚無組→命名→選值↔暫停操作頁面→設定→保存中→部分已存／已完成；取名是命名階段的子狀態。作用組、命名暫存、同步中及错误不能靠有沒有 DOM 輸入框推測。
- 選值→設定需完成屏障（R03）；設定→返回選值保存共用設定；保存中禁止切組與返回但不把正在保存的任務宣稱可取消；部分已存畫面保留「已建立哪些、未建立哪些、下一步」，不能將關閉解讀為刪除已存任務。
- 部分保存的每組狀態為已保存／待保存／失敗與原因，重試只處理未保存項；已保存組提供「開啟已建立任務」進既有編輯流程，不再回到新增草稿重建。放棄只清未存項，不刪已存任務。C1/F1 的重載測例必須驗畫面狀態而不只數 saveTask 呼叫次數。
- R07 的可存取性包括當前組狀態、來源與失效值可讀名稱；錯誤公告及結果通知復用既有 alert/status 元件，切組與同步回覆不反覆搶焦點、不逐 hover 讀出。讀屏／Tab 操作需驗組與值清單，而不只驗完成鈕。
- R08 的 frame 清單探測需驗「探測部分失敗」：目前 listFrames 外層例外直接回空清單。不可注入 frame 是否導致 API 整包失敗要在真實瀏覽器確認，不以推論當事實；任何整包失敗須顯示探測錯誤，並保留仍可驗證的健康來源，不假稱整頁沒有框架。
- R10 的來源即時重試只對可判定的暫時性定位／文件通訊問題，有獨立上限並共享 deadline；解析錯誤、權限拒絕、定位歧義不反覆重送。成功來源不重抓；沒有回覆的宣告 key 必須補失敗，未知額外 key 不進結果，空回覆不再靜默 return null。
- R11 也涵蓋 RUN_TASK 協定：整批 outcome 應依本次完整值結果區分全部完成／部分失敗／全部失敗（公開代碼暫定 done／partial／failed）。popup、任務頁、Picker 首次抓取一起更新；不能只讓 Picker 自查 values。回覆取本次執行身分的結果，不把同分鐘前一次手動結果混成此次成功。
- 暫停操作頁面只釋放頁面點擊／鍵盤攔截，不退出工作階段、不清選取；恢復先驗來源。可否將互斥狀態重播為排程仍由 D01 決定，不能把「能暫停切頁籤」當成「之後能自動重播」。
- C1 的跨 frame 協定要有順序與確認：命名／選值切換及 group 切換不能接受上一階段的點擊；當前 document 身分與 session／group／operation 身分共同校驗。全部列在同一份狀態轉移表並由可控制順序的測試驗證。
- 原 14 階段是作業層級，不足以直接每段派一個大改動。實作前再分：C1a 草稿、C1b 訊息／完成屏障；C2a frame 進出、C2b 文件生命週期；D1a 命名、D1b 群組管理；E2a 結果完整性、E2b 重試／復原、E2c 提交中斷；F2a 編輯重選、F2b 告警、F2c 報表投放、F2d 匯出入。每小段沿用對應 R 項驗收並獨立交付，不併入一個無法定位失敗原因的大測試。
- 加一條早期縱向驗收：B/C 最小契約完成後先跑「兩個來源→一組→保存→實際抓取→子序列畫面」，再擴充所有手勢與管理細節，提早抓資料鏈斷點；A 的完成鈕修正可獨立驗收，無需等整輪大改才確認原 bug。

### 13.4 上帝視角的最終交付門檻

1. 可選：同頁來源能進正確群組，命名與選值互不污染，所有退出有明確結果。
2. 可存：最後一次變更已同步、規格完整、部分保存可恢復且不重建已存任務。
3. 可再抓：新抓取頁面可重建必要狀態，定位語意與選取時一致；不只看目前頁面試抓。
4. 可追蹤：成功／部分失敗／整體失敗在預檢、報表、告警與診斷一致，舊序列不被誤配。
5. 可維護：schema 及來源模型唯一、呼叫端完整、失敗可定位、負載有界、升級及備份恢復可驗。
6. 本輪不承諾瞬間原子地擷取會變動的整頁；跨來源是有順序的觀察，需保留來源的擷取時刻，不能把先後數秒不同值假稱同一快照。紀錄新增時刻資訊若有必要，需驗報表聚合仍按既有 slot／capturedAt 契約。

以上任一層未驗收，不得用後面畫面看起來正常或單元測試數量增加來替代。

- 不承諾任意網站的狀態操作自動錄製、不可注入的 frame 或 closed shadow root；D01 需使用者設定可重播的來源動作，空動作不自動重載或回到初始狀態。
- R15 的最壞容量案例 100 次切組中位 ACK 約 1321ms，仍可能讓人感到慢；CDP 分段探針逾時，未能分離 drain、session 寫入與回傳成本。孤立 world 的內部快取數量亦無法直接觀察；Node 同站佇列數字不冒充真實 Chrome 基線。後續若優化，需維持 durable draft、revision 與 ACK 的契約並另做可比較量測。
- 不接觸或備份使用者實際瀏覽器資料；發布前需由使用者按 SPEC 的設定與歷史雙份匯出流程自行備份並驗檔。舊二進位拒收 schema 4 已在隔離 profile 實測，但不等於舊版可安全共用升級後的 local storage。
