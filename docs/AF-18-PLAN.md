## 批次 A：巢狀表格的已選值無損升到外層

### 現況與核對結果（探針實測於 `tests/fixtures/nested-monitor.html`）

1. **↑ 在已選之後無效**：`upgradeTarget` 的鎖定來源 `anchor` 以「已選那張表」優先於「↑ 明確選定的表」（`picker-mode.js:141`）。
   先點了小表的值 → 按 ↑（目標變外層）→ 滑鼠一動，`anchor` 是小表、外層包著它 → 拉回小表。
   探針 S3：`after ↑ target OUTER` → `after move target INNER`。SPEC §2 寫「鍵盤 ↑／↓ 不受鎖表限制」，程式與它矛盾。
2. **↑ 之後、滑鼠移動之前畫面沒有整欄標示**：`setTarget` 清掉 hover 標示且不重算（探針 S2：`after ↑ (no move) hover marks []`），看起來也像沒反應。
3. **先點 A 欄一格再按整欄 → 只得到 1 格**：`upgradeLastPickTo` 以已選那張表（1×2 小表）算整欄（探針 S4：`picked marks ["42"]`）；
   先 ↑ 再點則得到外層整欄 6 格並帶格內路徑（探針 S5），但這條路被第 1 點擋住。B 欄（時間）是外層的普通格，所以正常。
4. **跨列不能加選**：監控頁每一列的 A 欄各是獨立小表，`Ctrl` 點別列被「一個任務只能抓同一張表格」擋下（`:2345`）→ 實際上一格一個任務，這是 P4 的主因。
5. **已選標記畫錯表**（本輪發現）：`handleTableMouseMove` 以滑鼠所在的表重貼已選標記（`applyPickedMarks(currentTargetEl)`，15 個呼叫點傳 `currentTargetEl`）。
   探針 S4：已選的是第一列的 42，滑鼠移到第三列小表後藍框跑到 41。送出的值正確，畫面在說謊。
6. **跨表守門對內外層豁免**（`:2345-2346` 的 `contains` 條件）：目前靠鎖表走不到；修掉第 1 點後會變成走得到的路徑，必須一起處理。
7. 資料模型已支援目標形狀：外層 `(R, C)`＋格內路徑 `inner`（AF-15；`innerPathOf` 支援任意深度，`table.js:166`）。擷取端探針：外層整欄＋inner → `ok`、`used 6`、`items 9`。

### 定案

- **採「無損升到外層」**：預設仍指內層小表（既有任務的規格、預設行為零變動、不需遷移）。
  小表的值 `(r, c[, inner])` 可以無損換算成外層 `(R, C)`＋「從外層格到那個元素的完整路徑」。換算只有一份，三個時機觸發。
  - 不選「預設改指外層表」：舊式站台用版面表格包整頁，猜錯會產生很長、很脆弱的格內路徑，違反「判準不放寬」。
  - 不選「只修 ↑」：使用者仍得自己知道要按 ↑，跨列加選仍被擋。
- **外層表 O 的定義只有一份**：「從已選那張表 T 按一次 ↑ 會到的那張表」（沿用 `upgradeTarget` 的 deliberate 路徑，含 `innermostTable` 判準）。一次只升一層。
- **「可升級」的判準只有一份，三個觸發共用**（二次複檢新增——沒有它，本方案會重蹈「預設指外層」被否決的那個風險）：
  O 必須是「重複結構的資料表」，不是版面表格。判定：T 位於外層欄 C；O 的資料列中，**至少還有另一列**在 `(R, C)` 沿「外層格到 T 的路徑」解析得到一張
  **與 T 同型的表**（資料列數相同、第一列格數相同）。「什麼算一個」＝一個同型小表的外層列；**一個都沒有＝不可升級**。
  - 反例一（並排）：版面表格同一列的兩格各放一張資料表 → 同欄沒有第二張 → 不可升級，點另一張仍是「換表」。
  - 反例二（疊放不同型）：版面表格同一欄上下疊一張 1×3 摘要表與一張 20×5 資料表 → 不同型 → 不可升級。
    沒有這條，單列摘要表上選整欄會自動變成「版面表那一欄＋路徑」，把下面那張表第 1 列第 1 格靜默加進聚合，而且外層列標題是整張表串起來的文字、每次都變，天天黃燈。
  - 只對 HTML `<table>` 的巢狀啟用；ARIA／CSS 假表格的巢狀維持現況（本輪沒有實測樣本）。
  - 不可升級時：觸發 1 維持現況（小表整欄 1 格＋原提示句）、觸發 2 走既有換表規則、↑ 在已選非空時不換目標並說原因。
  - 判定結果以 T 為鍵快取，**不得在每次 `mousemove` 重掃整張外層表**；快取在 `exitPickMode` 清掉（會跨表殘留的狀態，AF-7／AF-9／AF-17 同型）。
- **`repick` 用途不升級**：升級會改掉每個值的定位，`sameSpec` 比不到 → 值的 key 重生、歷史序列斷掉。
  `repick` 下三個觸發時機都不升級，而且**不得靜默**：說「重選既有任務時不能換到外層表（歷史紀錄會接不上）；要抓外層整欄請建立新任務」。
  面板的「回頁面重選目標」走的是 `task` 用途（任務尚未儲存、沒有歷史），照常升級。
- **升級是全有或全無**：清單裡只要有一個值換算不了（多列小表的整欄／整列值、元素解析不到、沒有外層表），就整批不升、狀態不變、說出原因。
- **升級留一步反悔**：升級（含緊接著的那一次加選）之後 `Ctrl+Z`／「復原」一步回到升級前，連同「已選屬於哪張表」一起回去（沿用換表快照的形狀）。

### 改動

**A-1 換算機制、標記、↑／↓**（`src/content/picker-mode.js`）

1. 新增唯一一份換算：把目前清單全部換成外層座標，成功後「已選屬於哪張表」與目標都變成 O。
   - 單格值 → 外層單格值；列／欄標題取外層表的；`inner` ＝外層格到該元素的完整路徑（原本就帶 `inner` 的，路徑接到最末端元素）。
   - 小表**只有 1 列**時的整欄值 → 外層整欄值（`index` ＝外層欄、`inner` ＝外層格到小表那一格）；這是「建立」整欄值，照 `withFooterExclude` 做一次表尾排除並提示；小表值上原有的 `exclude` 丟棄（1 列沒有東西可排）。
   - 其餘整欄／整列值 → 換算不了（見定案「全有或全無」）。
   - 清單是空的 → 什麼都不做（↑ 照舊）。
2. **↑ 在已選非空時**：`task` 先升級再換目標並鎖在外層；升級不了（不可升級、換算不了）或 `repick` → **照樣換到外層並鎖在外層、值不動、說原因**
   （實作期推翻原定「不換目標」：那會拿掉 AF-10 C-5「↑ 到外層再點＝換表」這條路；見執行紀錄 A）。
3. **↓ 在已選屬於外層表時**：不換目標，說「已選的值在外層表；要回小表請先移除已選」。不得出現「按了、目標換了、滑鼠一動又回來」。
4. **↑／↓ 之後立刻以最後停留的那個元素重算 hover 標示**（不必等滑鼠移動）；沒有停留元素就不畫。
5. **已選標記一律畫在「已選屬於的那張表」上**；那張表不存在（清單空）才用目前目標。15 個傳 `currentTargetEl` 的呼叫點都要符合這條，不得只改 `handleTableMouseMove` 一處。

**A-2 兩個自動觸發**（`src/content/picker-mode.js`）

6. **觸發 1——單列小表上要整欄**：目標是單列巢狀小表（`isSingleRowNestedTable`）時，下列入口一律改成建立「外層整欄＋格內路徑」，已選若在小表先升級：
   整欄模式點格、工具列把最後一格升級成整欄（`upgradeLastPickTo`）、右鍵「這一欄：整欄聚合」、右鍵「這一欄：每格各一個值」（建立的是外層每一列的單格值）、
   沒選值直接送出的整欄路徑、`Enter` 快速路徑。整欄模式下 hover 標示同步改畫外層那一欄的同一個位置（畫面框到的＝點下去選到的）。
   原提示句 `SINGLE_ROW_NESTED_TABLE_NOTICE` 改成說明已經發生的事：「這張小表只有 1 列，已改選外層表這一欄的同一個位置（N 格）；只要這一格請切回單格」。
7. **觸發 2——跨到同一張外層表的別處**：已選在小表 T 時，滑鼠移到「O 的別列小表的格子」或「O 自己的格子」→ 目標指向 O（hover 標示以 O 的座標＋子單位計算）；
   在那裡點一下／`Ctrl` 點／`Shift` 點／拖曳框選／雙擊 → 先升級再照原語意處理。`Shift` 範圍的錨點用升級後的那一格。
   滑鼠回到 T 自己的格子 → 目標仍是 T（不升級、行為照舊）。移到非表格區域 → 目標不變（AF-10 的工具列可達性不動）。
   移到與 O 無關的另一張表 → 既有換表規則不變。
8. 第 6 點守門條件（`:2345`）同步收緊：內外層關係不再豁免——走得到的路徑只剩「已升級」或「擋下並說明」（`repick`、升級不了）。

## 批次 B：點一下＝加選；工具列第四段

### 現況與核對結果

- 點一下＝取代、`Ctrl` 點才加選（AF-8 依試算表習慣定案；`onClick` `:2363-2375`、`replaceSelection` 唯一呼叫點 `:2372`）。

- 「每格各一個值」只在右鍵選單（`col-each`，`handleMenuAction` `:1599-1628`，收尾設 `trimReady`）；BACKLOG 既有「工具列加第四段」一項，觸發條件（不好發現）已成立。
- 寫死三段的位置：`toolsDef` `:2670-2674`、Tab 循環 `:2138`、白名單 `:2225`、停用判定 `:714`、`currentAxis` `:2837`。
  斷言三段的測試：`p3:44,47,75-87,252,266`、`q1:62,64,92,100,162`、`s2:67,306`。

### 定案

- **表格內點一下＝加選，再點已選的＝取消**（`task` 與 `repick`）；`Ctrl`／`⌘` 點維持同義（不報錯、不教學）。推翻 AF-8「點一下取代」。

## 批次 D：儲存到關面板之間的缺口

（三次複檢改寫：使用者定案「多任務一開始就從右鍵決定」，原擬的「在這一頁再抓一個」鈕與「新建任務不自動關」**作廢**，改由批次 G 承接。

- 此時在頁面上再右鍵選一次：入口看到 `kind:'new'` 不寫等待態（`main.js:813-816`）；`PICKED` 回來時 `keepDraft` 成立 → `retarget:true`（`main.js:542-547`）→

### 定案

- **維持「存完 1.5 秒自動關」**：單任務使用者存完就是做完了，多留一顆「關閉」要他按是每次都付的成本；要一次建很多個的人走批次 G 的入口。

- 單任務的回饋區多一行提示（不是按鈕）：「同一頁還要抓別的？下次在右鍵選『一次建立多個任務』」——多任務入口只在右鍵，這是它最自然的曝光點。

### 改動

**D-1**（`picker.js`、`background/main.js`、`ui/popup/popup.js` 的入口條件如有自己一份）：如定案。`'saved'` 是 `panel:<tabId>` 形狀的新值，SPEC §2 的形狀說明要補。

- 資料模型是「一個任務＝一個定位目標（一張表或一個元素）」，同一張表可以多個值；同一頁四張表就是四個任務（SPEC §2）。本批次**不改這個模型**，改的是「一次選好、一次存好」。
- 選取模式的狀態是單一組：`selectedList`＋`pickedTableEl`；點不相干的另一張表＝換表取代（`onClick` 表格分支）；非表格是「點一下鎖定、完成才送出」。
- `confirmPick`（`picker-mode.js:1319-1453`）直接讀模組狀態組 `PICKED`：`locator`、`blockInfo`、`picks`、`nameHint`、`preview`／`previewValue`——沒有「給一組目標就組一份」的函式。
- background 的 `PICKED`（`main.js:520-548`）把單一 payload 寫成 `kind:'new'` 的 ctx；`DESCEND_FRAME` 只帶 `purpose`／`taskId`／`preselect`。
- `handleSave`（`picker.js:2070-2177`）是單任務、全程讀 DOM：`getFormData` → `validateForm` → `buildTask` → `saveTask` → `REBUILD_ALARMS` → 寫 `pickerDefaults.last` → 依勾選的卡片型別 `addCard`。
  `render(ctx)` 把「由選取結果推得的欄位」（模式、block、多值清單與預設名稱）算進 DOM——沒有不經 DOM 的組任務路徑。
- 預設任務名稱的退路常落到 `nameHint`（caption → 前一個標題 → **頁面 title**）：同一頁的幾張表很可能得到同一個名字。
- 排程端不會因此多開頁：同站台任務串行（`enqueueForOrigin`），先跑的任務開的分頁留到佇列清空才關，後面的任務以 `tabs.query({url})` 找到並沿用（`fetcher.js:272-300,412-434`）——
  同一頁 N 個任務同一槽只開一次頁，這個模型撐得住批次建立。

### 定案

- **入口**：右鍵選單新增「一次建立多個任務」（`af-pick-batch`），排在「選取要抓的內容」下面。popup 不加（使用者指定右鍵；進 BACKLOG）。
  是否多任務**在入口就決定**，選取模式中不提供切換。
- **不開新用途，用旗標**：`ENTER_PICK`／`DESCEND_FRAME` 多帶 `batch: true`，`purpose` 仍是 `'task'`——`isMultiPickPurpose` 等數十個以 `purpose` 分支的判斷不必動。
- **選取模式的「組」**：一組＝一個定位目標（一張表，或一個非表格元素）＝將來的一個任務。
  - 批次模式下點不相干的另一張表的格子＝**開新的一組**（原本那組原樣留著，不取代、不必確認）；再回去點先前那張表＝回到那一組繼續加減。
    所有既有的表格內操作（加選、`Shift`、拖曳、工具列四段、右鍵排除、去頭去尾、批次 A 的升到外層）都作用在「目前這一組」。
  - **先後順序：能升到外層的先升，升不了的才開新組**。監控頁每一列的小表彼此是「不相干的表」，但它們同屬一張可升級的外層表——
    點別列的小表要走批次 A 的觸發 2（併進同一組、同一個任務），不得變成六個組六個任務。
  - 非表格元素：點一下＝把它加成一組，再點一次＝移除（批次模式沒有「鎖定」這個中間狀態）。整欄／整列模式下點非表格元素仍照既有規則拒絕並說明。
  - 空的組（值被移光）自動消失。上限：每組沿用 `maxPicks`，**組數上限 20（暫定）**，到頂要說明、不得靜默丟掉。
  - 已選標記與送出後的 `held` 藍框涵蓋**每一組**；面板的 chip 依組分段，段首是「任務 N：〈名稱提示〉（M 個值）」並可整組移除。
  - 指令句：沒有任何組 → 「點你要抓的內容；不同的表格或元素會各自成為一個任務」；有組 → 「已選 N 個任務、共 M 個值，好了按完成」。
  - **復原快照涵蓋整批**（所有組與目前是哪一組），不得只還原目前這一組。`exitPickMode` 重設全部組狀態（以「連續選兩次」驗）。
  - **框架**：一批只能在同一個框架內。批次模式下，已經有組時不得鑽進 iframe 代理層——說「進入框架會離開這一頁的選取；請先完成這一批，再對框架內的內容另開一批」；
    還沒有任何組時可以鑽，`batch` 旗標隨 `DESCEND_FRAME` 帶下去。
- **送出的形狀**：兩組以上 → `PICKED{ purpose:'task', batch:[…] }`，每個元素與單任務的 payload **同形**（`locator`、`blockInfo`、`picks`、`nameHint`、`preview`、`previewValue`、`previewSamples`）；
  **只有一組 → 送既有的單任務形狀**（使用者得到完整表單，不必為了一個任務走批次畫面）。
  「給一組目標組一份 payload」抽成一份，單任務與批次共用，不得複製 `confirmPick` 那一段。
- **面板的批次畫面**（`kind:'batch'`）——第一版刻意做薄：
  - 上半是任務清單：每列一個名稱輸入框、一句「抓什麼」（`describeTarget`，與其他畫面同一份）、「試抓」結果欄、移除鈕。
  - 下半是**共用**設定：多久抓一次、抓完放哪裡（含卡片型別）、整欄／整列的合成方式——沿用既有那幾個區塊的同一份 DOM 與 `pickerDefaults`。
  - 不提供逐任務的進階設定（定位方式、略過頭尾、正規表達式、前置動作、告警）。清單下方說明：「要個別調整的，存完到任務頁按編輯」。需要前置動作的頁面請用單一任務。
  - 「全部試抓」：逐一對每個任務跑既有的 `TEST_TASK`，結果回到各自那一列（值，或失敗原因）；整欄值附「用了幾格」的那句。批次畫面不畫逐格明細表。
    進行中按鈕顯示「試抓中 2／5…」且不可連按；「全部儲存」同理（「儲存中 2／5…」）。
  - 在清單裡把任務移除到一個都不剩＝取消（與按「取消」同一條收尾）；剩一個時仍留在批次畫面（不中途換成單任務表單，使用者填的共用設定才不會不見）。
  - **共用設定以畫面上那一份為準**：逐一走 `render` 收集時，`render`／`applyPickerDefaults` 會把排程與去處重設成預設值——
    每個任務收集前都要把使用者在批次畫面上的共用設定貼回去；儲存迴圈結束（不論成功失敗）畫面仍是批次清單，不得露出單任務表單。
  - 草稿以項目的**穩定鍵**對應（不是清單序號）：移除中間一項後，其餘各列的名稱不得錯位。
  - **預設名稱在同一批內不得重複**：各自照既有命名規則算，撞名的依序加「(2)」「(3)」；使用者手動改過的不動。
- **全部儲存**：逐一儲存，**每個任務都走既有的「`render` → 收集表單 → `buildTask`」那條路**，不得另寫一份從選取結果直接組任務的邏輯（兩份就會分岔）。
  `handleSave` 的核心（組任務、存、加卡片）抽成可重複呼叫的一份，單任務與批次共用；`REBUILD_ALARMS` 與 `pickerDefaults.last` 整批只做一次。
  - **部分失敗**：停在失敗的那一個，說「已儲存 k−1 個；第 k 個『名稱』失敗：原因」；**已存的從清單移除**，再按一次不會重複建立。
  - 卡片：每個任務各自依共用的卡片型別勾選建立（結果與一個一個建完全相同）；不想要就選「不加入」。合併成一張卡進 BACKLOG。
  - 成功：回饋區「已儲存 N 個任務。下次抓取：HH:mm」，之後與單任務同一條收尾（批次 D 的 `'saved'`）。
- **面板已有填到一半的表單時**（`kind:'new'`／`'edit'`）按批次入口：不進選取模式、不動草稿，面板顯示「有一個任務設定到一半，請先儲存或取消，再開始多任務」。
  反方向（批次畫面開著時按單任務入口）同理。批次畫面的草稿（名稱與共用設定）照樣寫進 session，切分頁回來不得清空。
- `repick` 與編輯既有任務不受影響：批次建出來的就是一般任務。

### 現況與核對結果

- AF-9 定案「不做獨立教學頁（使用者不會看），以面板指令句取代」；BACKLOG 留有「popup 的使用說明」。本輪依使用者要求**推翻**。

### 定案

- **位置**：`src/ui/help/help.html`（＋必要時 `help.js`），樣式走 `theme.css`＋`ui.css`＋頁內版面規則，亮暗雙軌。
- **入口只有一個**：右鍵選單最後一個子項「使用教學」（`af-open-help`；批次 G 之後右鍵共五項：選取要抓的內容／一次建立多個任務／設定此站台登入／開啟報表／使用教學），開新分頁。設定頁加開關「在右鍵選單顯示使用教學」。
  設定鍵 `showHelpMenu`：**缺省視為顯示，只有字面 `false` 才隱藏**（舊使用者升級後不能消失）；切換後右鍵選單當場反映，不必重新載入擴充功能。
  - **關掉之後仍要找得到**（二次複檢新增）：入口只有右鍵一項，關掉就等於整頁教學消失。設定頁那個開關旁邊固定放一個「開啟使用教學」連結
    （它是開關的附屬，不算另一個入口）；教學頁頁尾也說明「右鍵這一項可以在設定關閉」。
  - **任何途徑改到這個設定，選單都要跟上**：設定頁切換、設定檔匯入（`settings-io`）兩條都要；現況 `setupContextMenus` 只在 `onInstalled` 呼叫（`main.js:281`）。
    重建要串行化（連續兩次切換不得交錯成 `removeAll`／`create` 互踩）。
  - **主題**：教學頁要照 `settings.theme`（系統／亮／暗）顯示。現況 `applyTheme` 寫在 `report.js:90`，**只有 Report 頁套用**——
    Picker、站台設定、popup 都只跟系統走、不理使用者的主題設定（本輪發現的既有不一致，是否一併修見「待決」）。
    教學頁需要它，所以 `applyTheme` 搬到共用位置（`ui/` 下、Report 改 import），不得複製一份。
    **三次複檢定案：Picker、站台設定、popup 一併套用**（E-0）。理由：使用者在設定頁選了暗色，側邊面板卻是亮的，是看得見的不一致；
    共用函式搬好之後每頁只是多呼叫一次。限制：各頁在自己的初始化流程裡呼叫（專案規定 UI 模組載入時不得讀 storage）；
    設定讀到之前先跟系統走，會有一瞬間的色差（Report 現況相同，不另處理）；設定頁切換主題時，已開著的其他頁要到下次載入才換（不做即時廣播）。
- **示意圖用 HTML/CSS 畫**（不用截圖）：一張迷你表格元件套上各種狀態（橘框待選、藍框已選、虛線排除、工具列四段、已選 chip、設定面板摘要卡），顏色取 `theme.css` 變數。
  不做動畫——步驟以並排的靜態分格呈現。
- **寫法契約（P5 的本體，全部可機器檢查）**：
  1. 首屏只有「三步開始」（在網頁上按右鍵選取 → 按儲存 → 看報表），其餘在下方。
  2. 章節依「我想要…」分，每節固定四塊：一句目的（≤ 40 字）→ 步驟（**最多 5 步、每步一句 ≤ 40 字**）→ 一張示意圖 → 預設收合的「遇到這些狀況」。
  3. 主畫面（摺疊區以外）**不出現內部名詞**：`locator`、`inner`、`block`、`spec`、`preselect`、`frame`、`iframe`、聚合、定位器、子路徑、規格。
     「聚合」說成「合成一個數字」；`iframe` 說成「頁面裡的內嵌框」。
  4. 教學裡提到的按鈕／選單名稱一律標 `data-ui-label`，文字必須與程式碼裡的實際字串一致。

## 明確不做（本輪定案）

| 項目 | 理由 |
|---|---|
| 預設目標改指外層表 | 版面表格站台會得到脆弱的長路徑；升到外層已涵蓋需求 |
| 多任務的逐任務進階設定（定位方式、略過頭尾、正規表達式、前置動作、告警） | 第一版刻意做薄：共用排程與去處、各自命名；個別調整存完到任務頁編輯。要做就得把單任務表單做成可重複的元件，另開一輪 |
| 多任務的 popup 入口、跨框架同一批、整批合併成一張卡片 | 使用者指定入口在右鍵；一個選取階段只活在一個框架；合併卡片受折線 8 條上限牽制。皆進 BACKLOG |
| 儲存後「在這一頁再抓一個」鈕、新建任務存完不自動關 | 使用者定案「一開始就決定要不要多任務」；留著會讓每次單任務儲存都多一顆要按的「關閉」 |
| `repick` 用途升到外層 | 值的 key 會重生、歷史序列斷掉；需要另案設計新舊值對應 |
| 單欄小表上的「整列」自動升級 | 少見；只做整欄，進 BACKLOG |
| 工具列「整列→每格」 | 四段已是窄頁上限，留在右鍵選單 |
| 教學頁可動手的練習表格、截圖、動畫 | 擴充功能頁不能注入 content script，要另做示範模式；截圖會過期；使用者已選 HTML/CSS 示意圖 |
| 教學頁的其他入口（popup／首次安裝自動開／面板「？」） | 使用者指定只放右鍵選單；進 BACKLOG |
| 明細表回頁面上色、點一列設成略過 | 既有 BACKLOG，觸發條件未成立 |

### 多任務（批次 G）的多角度走查

**使用者角度**

| 情境 | 走查 | 處置 |
|---|---|---|
| 監控頁、批次模式、點不同列的小表 | 小表彼此是「不相干的表」，照字面會變成六組六個任務 | 明訂先後：能升到外層的先升（同一組），升不了才開新組 |
| 批次模式只選了一張表就按完成 | 走批次畫面會拿不到完整表單，白白降級 | 只有一組時送單任務形狀 |
| 三張表的預設名稱都是頁面標題 | 任務頁出現三個同名任務，分不出誰是誰 | 同一批內撞名加序號；手動改過的不動 |
| 第 2 個任務存檔失敗，使用者再按一次 | 第 1 個會被建兩次 | 已存的從清單移除；訊息說清楚存了幾個、誰失敗 |
| 在批次畫面改了排程，存出來卻是預設值 | 逐一 `render` 會把共用區重設 | 每個任務收集前把畫面上的共用設定貼回去；驗收比對存下來的值 |
| 想對其中一個任務設「取最大值」或前置動作 | 第一版不支援個別進階設定 | 畫面上直接說「存完到任務頁編輯」；教學頁誠實寫；逐任務設定進 BACKLOG |
| 表單填到一半又按多任務入口 | 靜默洗掉草稿，或把批次結果硬塞進單任務表單 | 兩個方向都拒絕並說明，不動草稿 |
| 全部試抓要跑十幾秒 | 沒進度、可連按 | 「試抓中 2／5…」、不可連按 |
| 已經選了兩組才發現目標在 iframe 裡 | 鑽進框架會丟掉已選 | 已有組時不鑽、說明原因；沒有組時可鑽且旗標帶下去 |

**程式面角度**

- 入口條件現況就有兩份，再加三個條件前先收成一份（G-2）。
- `handleSave` 是 DOM 驅動的單體：先做「抽核心、行為不變」的 G-3a 並單獨驗收，再疊批次畫面（G-3b）；批次儲存一律走 `render → 收集 → buildTask`，
  以「同一份選取結果，批次存的規格＝單任務存的規格」當守門，杜絕第二份組任務邏輯。
- `confirmPick` 的 payload 組裝抽成一份（單任務與每一組共用），以「只有一組時訊息逐欄相同」守門；`previewSamples`（批次 C）要在抽取之後才不會漏在其中一邊——**C-2 排在 G-1 之前已滿足**。
- 復原快照要涵蓋整批；`exitPickMode` 重設清單再多一組狀態，仍以「連續選兩次」驗。
- 批次 A 的升級與批次 G 的開新組在 `onClick` 同一個分支交會：G-1 的規格檔要把批次 A 的判準當既有契約引用，不得重寫。

**管理者角度**
