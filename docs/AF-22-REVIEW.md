## 1. 先走使用者的完整流程

| 角色與合理質疑 | 場景核對 | 審查結果與處理 |
|---|---|---|
| 初次使用：「完成了怎麼還沒建立？」 | 建群組→取名→選值→完成→排程→儲存 | 初稿有兩階段但缺結果承諾；補「完成選取尚未建任務」與最後任務／值／排程／卡片摘要，PLAN R07。 |
| 快速操作者：「我最後點的值怎麼不見了？」 | 最後一筆選取訊息未抵達，立刻按完成 | 只寫草稿 revision 不足；補 ACK、操作去重、完成屏障，R03。 |
| 大量分組者：「你到底把值加去哪組？」 | frame 尚未收到切組，使用者繼續點值 | 需顯示當前組、切換確認及中止舊手勢；增加未存值移組與重複處理，R02。 |
| 常反悔者：「刪一個值復原，為何別組名稱也倒退？」 | 全草稿快照→改名→Undo | 初稿快照含名稱但未定義失效；補局部還原或快照失效，不回滾後續無關編輯，R06。 |
| 想換頁籤者：「同頁能選，為什麼我開另一個頁籤就不能存？」 | 選網頁頁籤 A→切 B→A 的 DOM 被卸載 | 原先選取攔截缺暫停入口，且選好後要求全部立即重定位與互斥內容衝突；補暫停狀態，排程重播列 D01。 |
| 依賴排程者：「剛才試抓成功，明天為什麼失敗？」 | 當前頁已登入、展開、捲動；新抓取頁沒有這些狀態 | 必須區分當前頁試抓與新頁重播驗證；不能以目前 DOM 成功保證排程，D01。 |
| 誤關面板者：「按 X 就把半小時白做了？」 | 原生 X→再開→目前 closePanelFor 清 ctx | 原稿「恢復」與「沿用關閉」互相衝突，已移除模糊語句，D02 建議保留 session 草稿。 |
| 熟悉舊版者：「雙擊一個數字為何整批結束？」 | click、click、dblclick 既改選取又可能送整批 | 原稿沿用快捷鍵但未完整定義序列；D03 建議新群組改固定按鈕／明示快捷鍵，舊入口不變。 |
| 長名稱／中文輸入者：「我的名稱被截斷、Enter 把表單送走？」 | 欄位取名、長文字、IME、contenteditable、空值 | 補取名範圍預覽、文字 input 取值、不讀密碼、完整名稱、焦點規則，R04/R07。 |
| 窄螢幕與鍵盤使用者：「按鈕有寫在 DOM 不代表我能按。」 | 200% 縮放、Tab 導覽、刪組後焦點、錯誤定位 | A 原已有真瀏覽器驗收，R07 補焦點、控制項與縮放；不宣稱網頁任意位置已有完整鍵盤探索。 |
| 大量選值者：「超限就悄悄漏幾個還叫完成？」 | 99 值再展開 3 格、空組、整欄與單格重疊 | 補全有或全無、空組直接修復入口、不同擷取規格可共存，R05。 |
| 故障恢復者：「任務到底存了沒？再按會不會重複？」 | 第 k 組保存失敗、worker 回覆遺失、首次抓取中斷 | 穩定 task id 僅處理任務新增，不等於抓取副作用可重送；補保存狀態與待確認結果，R13。 |
| 管理混合資料者：「一個值正常，整個任務就顯示綠？」 | multi 一值成功、一值失敗；預檢 any success=ok | 是現有程式與新契約的落差；預檢需同口徑顯示部分失敗，R11。 |
| 管理文字狀態者：「說支援文字，告警只能輸入數字？」 | 設定「狀態等於正常」 | evaluator 有文字分支但表單與保存只收數字；補完整告警輸入與保存鏈，R12。 |
| 局部失敗者：「壞一個值為什麼整組重來？」 | 五值中一值失效 | 補單值修復與取消的明確邊界，其他值不變；真正換指標需說明歷史分界，R18。 |
| 同名任務管理者：「兩個價格，我該刪哪一個？」 | 同名組保存後離開原群組順序 | 補來源摘要與穩定輔助識別，延伸到確認／通知／匯出，R19。原自動建議名加尾碼與手動同名不同，不能一概推翻。 |

## 3. 管理者與維護者角度

1. **發布範圍可控。** A 的原 bug 修正可獨立驗收。B–F 是一條資料鏈，中間半成品不能開放新入口；新模式的 enum／schema 一定先收斂，不能代理各自新增同義欄位。
2. **回退可執行。** 升級前備份與恢復演練，用既有匯出機制即可；不要增加自動備份服務。新版資料不得只改 schema 數字就交給舊版。
3. **負載有界。** 20 組×100 值不是原本一張表 100 格的同一成本；frame 探測、session 整包更新、圖表卡片數與同站台等待都需量測。R15 要求最大情境、消息與寫入次數、快取失效與資源釋放。
4. **錯誤可處理。** 管理者要看「哪個任務、哪個值、哪個來源、卡在哪一步、下步怎麼做」，不是 2000 個內部 key。R09/R11/R17 統一結果口徑，摘要有上限、可進一步查看。
5. **部分保存可對帳。** 已存與未存分開，已存 task id 不能在返回選取時重生；抓取結果未知必須說未知，不能假稱失敗再自動重送。
6. **權限與隱私沿用最小必要。** 跨 iframe 不等於讀整頁所有表單；名稱取值不讀 password，診斷不新增 token／完整 HTML 收集。若實作需要新增權限，先提出理由與原有能力差距，不預先假設必須擴權。
7. **驗收粒度足夠。** 初稿 14 階段中 F2 涵蓋編輯、重選、拆分、告警、報表、匯出入，不能實作時整包派出。PLAN §13.2 已列下一層小段與早期縱向測試。

## 4. 最後從頭串起整體影響

檢查順序為「頁面手勢→命名／群組→操作訊息→session 草稿→完成屏障→表單→永久任務→新抓取頁→來源定位／動作→逐值結果→紀錄／帳本／health→告警／報表→編輯重選→匯出入→升級／回退」。

每一段都追兩個方向：前段新加的資訊後段是否真的消費；後段需要的來源、型別與 key 是否真的由前段產生。以下是複檢後不能省略的聯合測例：

| 測例 | 必須同時成立 |
|---|---|
| 兩表同座標＋同 URL 的兩 frame | 選取不誤配、保存有來源、排程唯一定位、重選不換 key、告警指對值 |
| 最後一點立即完成＋訊息重送 | 最終清單完整、toggle 不反轉、不重複 field、同一同步屏障 |
| 組 1 正常、組 2 空、組 3 名稱待同步 | 明確逐組修正；不因目前組完整而送出其他未完成組 |
| 一來源失敗＋另一來源成功＋預檢 | 成功保留、失敗可見、預檢不全綠、父帳本只結一次、沒有來源獨立 alarm |
| 離線／登入失敗／worker 中斷 | 每個宣告子序列有失敗資訊；失敗 N 次告警有正確歷史，不只父紀錄 |
| 已存任務回覆丟失＋首次抓取回覆丟失 | 不新增第二份任務、不盲目重送外部動作、顯示待確認，手動再抓是新明確操作 |
| 舊抓取執行中移除 field | 舊結果不復活已移除來源，歷史保留，其他 field 持續正常 |
| 互斥頁籤 A/B＋全新抓取頁 | 依 D01 定案驗證可重播，或明確提示無法重播；不能只在當前頁驗 |
| 混合數字／文字群組 | 保存型別、文字告警、父任務投放、子序列投放、範本與匯出一貫 |
| 升級舊資料→新群組→設定匯出入→備份恢復 | 舊 ID／key 不漂移、新形狀完整、舊版不誤收、恢復損失範圍可知 |

跨來源抓取是先後觀察，不是整頁原子快照。來源在數秒內變動時要避免對時間做錯誤承諾；來源擷取時刻與報表原 slot／capturedAt 規則需一起驗，不為呈現好看把時間全部改成最後來源完成時刻。

## 5. 三項已定案與最終判斷

使用者已授權依建議方案開始實作，定案為：

1. **D01：同輪加入來源取得順序與必要頁面操作。** 可延續「同頁不因表格限制」的方向；成本是要補來源狀態與重播流程。另一方案是僅支援穩定共存來源，但會縮小原期待。
2. **D02：關閉面板先暫停、同次瀏覽器工作階段保留草稿。** 重開可繼續或放棄；不是永久自動保存。
3. **D03：新群組不以雙擊／普通 Enter 完成整批。** 使用固定按鈕與明示 Ctrl/Cmd+Enter；舊單任務操作維持。

以上已在 PLAN §13.3 標記定案。其他補強均已落入契約、階段與驗收；未把計畫描述為功能已完成。結論是「開始依完整方案實作」，正確運作仍必須等逐段與真實瀏覽器端到端驗收。
